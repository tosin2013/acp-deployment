## Hardening Cycles

Two post-incident hardening cycles were completed during this release:

### Cycle 1 — ODF Multus/KVM Incident
**Report:** [`docs/hardening/odf-multus-kvm-v4.21-2026-06-04.md`](../hardening/odf-multus-kvm-v4.21-2026-06-04.md)

Root causes resolved:
1. ODF Multus macvlan incompatibility with KVM virtio — `odf_use_multus: false` gate
2. LSO `NonRotational` filter excluded KVM virtual disks — added `Rotational` to LSO vars
3. Ansible `combine()` integer coercion on `count` field — explicit `| int` at call site
4. ODF pods pending due to memory pressure — VM RAM raised to 48 GiB

### Cycle 2 — Post-Install Pipeline Incident
**Report:** [`docs/hardening/post-install-pipeline-v4.21-2026-06-04.md`](../hardening/post-install-pipeline-v4.21-2026-06-04.md)

Root causes resolved:
1. CertManager CR wrong `apiVersion` (`acme.cert-manager.io/v1` → `operator.openshift.io/v1alpha1`)
2. Missing OLM CSV wait after cert-manager Subscription creation
3. `ansible_user` undefined for `ansible_connection: local` — explicit inventory setting + fallback
4. kubeconfig CA not stripped after API cert rotation — handler fixed, manual remediation documented

## Known Limitations

| # | Limitation | Impact | Workaround |
|---|-----------|--------|-----------|
| 1 | Nested virtualisation required for OpenShift Virt on KVM | Cannot run VM workloads on non-KVM-capable hosts | Use IBM Cloud bare-metal with nested KVM enabled |
| 2 | ODF not supported on SNO (single-node) | SNO deployments have no Ceph/NooBaa | Use ephemeral or external storage for SNO |
| 3 | `odf_use_multus: false` required on KVM | ODF storage traffic shares the primary network | Accept co-mingled traffic; Multus only for bare-metal |
| 4 | ZeroSSL EAB credentials required for TLS | Cannot use self-signed or Let's Encrypt without code change | Create ZeroSSL account at app.zerossl.com/developer |
| 5 | Route53 required for DNS-01 TLS challenge | Other DNS providers need code changes in ClusterIssuer | Use Route53 IAM user with programmatic access |

## Deploy Commands (Exact)

Full pipeline (IBM Cloud KVM):

```bash
# Step 1: Prepare environment
git clone https://github.com/tosin2013/acp-deployment.git
cd acp-deployment
./hack/bootstrap.sh
./hack/install-kvm-host.sh
./hack/setup-libvirt-networks.sh
./hack/generate-kvm-macs.sh

# Step 2: Configure
./hack/select-cluster-topology.sh ibm-cloud-converged
./hack/setup-cluster-vars.sh
vi examples/ibm-cloud-active/extra-vars.yml

# Step 3: Deploy cluster
./hack/deploy-cluster.sh \
  -i examples/ibm-cloud-active/inventory.yml \
  -e @examples/ibm-cloud-active/extra-vars.yml

# Step 4: Post-install services
ansible-playbook playbooks/site-post-install.yml \
  -i examples/ibm-cloud-active/inventory.yml \
  -e @examples/ibm-cloud-active/extra-vars.yml
```

Validation:

```bash
export KUBECONFIG=~/cluster_acp/install/auth/kubeconfig
oc get nodes
oc get co | grep -v "True.*False.*False"    # all operators healthy
oc get storagecluster -n openshift-storage   # HEALTH_OK
oc get csv -n cert-manager-operator         # Succeeded
oc get hyperconverged -n openshift-cnv      # Available
oc get AutomationController -n aap          # Running
```

## Upgrade Path

This is the first tagged release. Future releases will follow the OCP minor version track
(v4.21.x for patch updates, v4.22.0 for the next minor bump).

To upgrade from an unversioned pre-v4.21.0 state:
1. Read all amended ADRs (0003, 0004, 0005, 0006, 0009)
2. Apply the `odf_use_multus` and `odf_device_count` variables to `extra-vars.yml`
3. Update `ansible_user` in `inventory.yml`
4. Re-run `site-post-install.yml` — all roles are idempotent
